# 3. IMPLEMENTATION-READY HARD GATE

Every EQ3 reference / packet must provide enough information for a competent implementer to build it without returning to research or inventing design DNA.

Required where applicable:

A. SEMANTIC INPUT CONTRACT
- activation conditions
- semantic state/data requirements
- optional inputs
- invalid/unsupported states
- deterministic fallback

B. PROJECTION LOGIC
- source mechanism → UI behavior mapping
- precedence
- selector/variant logic
- forbidden combinations
- UNKNOWN behavior

C. COMPONENT / SEMANTIC-ZONE CONTRACT
- allowed zones
- prohibited zones
- dominance/ownership
- Reading Sanctuary demotion
- archetype interaction where relevant

D. RESPONSIVE CONTRACT
- desktop
- tablet if materially distinct
- mobile
- collapse behavior
- identity invariants across viewport changes

E. INTERACTION CONTRACT
Where applicable:
- triggers
- transitions
- focus/keyboard/touch equivalence
- state continuity
- reduced-motion behavior
- no critical information hidden behind decorative interaction

F. VISUAL / BEHAVIORAL TOKEN ENVELOPE
Provide bounded implementable controls for applicable axes such as:
- spacing
- density
- hierarchy
- line/edge emphasis
- layering/depth
- border/joint treatment
- opacity/transmission/reflection
- repetition
- motion class
- scale/granularity
- information density
- texture/noise limits

Do not invent false numerical precision.

G. ACCESSIBILITY ACCEPTANCE
- WCAG 2.2 AA where applicable
- contrast
- focus visibility
- text legibility
- target separation
- reduced motion
- cognitive density
- glare/visual-noise control
- semantic equivalence in fallback modes

STATIC

# 4. PROHIBITED EQ3 AMBIGUITY

The following are incompatible with implementation-ready EQ3:

- “implementer decides”
- “adjust aesthetically”
- “use suitable spacing”
- “use an appropriate motif”
- “inspired by”
- undefined selector behavior
- undefined UNKNOWN behavior
- unresolved semantic ownership
- unresolved responsive behavior
- unresolved accessibility fallback
- unresolved asset-off survival
- unresolved negative fixture
- unresolved nearest-neighbor differentiation

If these remain materially necessary to build the reference, it is not implementation-ready.

Previous EQ3 locks remain historically valid as research checkpoints.

However, before implementation, all previously locked EQ3 corpora must pass a GLOBAL IMPLEMENTATION-READINESS AUDIT against this amendment.
